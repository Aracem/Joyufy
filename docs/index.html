What it does

Wealth tracking, the practical way

Three account types (bank, cash, investment), one euro currency, weekly snapshots for what you can't transact on directly. No login, no cloud account required.

▲

Total wealth chart

Area or bar visualisations across 6 ranges from 1 week to all-time. Per-account breakdown.

●

Three account types

Bank and cash use a transaction model. Investment uses weekly value snapshots — no manual P&L math.

⇄

Smart transfers

Move money between accounts in one action — the app records both legs and excludes them from income/expense totals.

★

34 bank presets

Type "Santander" or "TradeRepublic" and the app suggests the logo and brand colour automatically.

↻

Drive backup

Optional sync to your own Google Drive. Auto-upload on close, auto-restore on open. Off by default.

Architecture

Four layers, one direction

MVVM with StateFlow<UiState>. Each layer depends only on the one beneath it. Domain is pure Kotlin — no Compose, no SQL.

Why this matters: domain models are pure — they can be unit-tested without a SQLite driver or Compose runtime. The Google Drive layer is desktop-only via expect/actual so the codebase stays portable to other targets later.
Data model

Three tables, one invariant

Everything fits in three SQLite tables with foreign-key cascades. The trickiest piece is how transfers are stored.

Transfers are two transactions, not one. Sending €100 from A → B writes EXPENSE on A and INCOME on B, both with related_account_id pointing at the other account. That makes per-account balances trivially correct (net zero across the pair), but income/expense aggregations must filter related_account_id IS NULL to exclude both legs.
Tech stack

Why each piece

Every choice optimises for one thing: a single Kotlin codebase that delivers a polished native desktop app on three operating systems.

Compose Multiplatform

JetBrains' port of Jetpack Compose to JVM and beyond. Same declarative UI model as Compose for Android, but renders natively on macOS, Windows and Linux. Keeps the door open for an Android target later without rewriting screens.

SQLDelight

Writes the SQL, generates the Kotlin. Type-safe queries, Flow integration, and zero ORM mystery. The full schema is one .sq file you can read in two minutes.

Koin

Lightweight DI without annotation processing. The whole object graph fits in a 40-line Koin.kt. Inject in composables via koinInject() — no Hilt boilerplate.

Ktor (Drive only)

Google doesn't ship a Kotlin Multiplatform Drive SDK, so the integration talks the REST API directly with Ktor's CIO engine. About 250 lines for OAuth2 plus upload/download.
